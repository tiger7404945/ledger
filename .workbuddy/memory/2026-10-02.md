## 落地的改动

- **S7-9 种子分层**：`mock/seed.js` 拆 `buildBase()`（账本 + 42 分类）与 `buildDemoBills()`（演示账单）；
  `DEMO_ENABLED` 用 `try { import.meta.env.DEV } catch { NODE_ENV }` 兼顾 Vite 与 Node；
  `seed` 参数三态化；`runSeedMigration()` 只在播了演示账单时跑。
- **S7-1**：`ensureSignedIn()` 不再 `signInAnonymously()`，拿不到已持久化登录态就抛 `NOT_SIGNED_IN`；
  新增 `resumeFormalUser()`，`getIdentity()` 对匿名身份返 `uid: null`。
- **S7-2**：未登录分区 `ledger_anon` → `ledger_guest`（`GUEST_ACCOUNT_PREFIX`）；
  `buildInstance()` 对 guest 传 `seed: IS_DEV ? 'full' : 'base'` + `migrateFrom: false`；
  账号分区传 `seedCategoryUpdatedAt: 0`。
- **S7-3**：`switchPartition(null)` 只 `stop()`；`tryReauth()` 只复用现有登录态；`AUTH_EXPIRED` 文案改
  「登录状态已失效，请重新登录」；`sync()` 新增 `cloud.signedIn === false` 短路。
- **S7-4**：`components/LoginSheet.vue` + `composables/useLoginSheet.js`（模块级单例），挂到 `App.vue`。
- **S7-5**：`composables/useLoginGate.js`（`shouldAllowWrite` / `requireLogin`）；`/record`、`/category*`
  加 `meta.requiresAuth`；守卫注册在草稿守卫**之前**。
- **S7-6 / S7-7**：`ACCOUNT_PHASE` 收敛两态；删除转正链路、`core/firstBind.js`、首绑裁决弹框；
  新增 `db.enqueueAll()` + `enqueueLocalForCloud()` 替代 `ensureCloudFirstBind`。

## 踩到的坑（七条，详见 `phase2-backend-plan.md` 的「实施记录」）

1. 旧匿名登录态被当成「已登录」（显示「已登录 · 0OuzUrrt」并开错分区）→ 加 `resumeFormalUser()` + 匿名判空。
2. 已登录时点「+」被**假拦截** → `bootstrap()` 只在 `MineView.onMounted` 调过；`liveGateContext` 取并集。
3. 直接访问 `#/record` **白屏** → 守卫 `return false` 中止导航；首次进入要 `{path:'/',replace:true}`。
4. 守卫注册顺序：门禁必须在 `installRecordDraftGuard` 之前，否则草稿被误清。
5. `seed-test` 在 Windows 撞 `EBUSY`（`execFileSync` 起子进程）→ 改「同 URL 加 `?prod=1` 破坏 ESM 缓存」。
6. `gate-test` 路由表扫描窗口截错（320 字符窗口把后一个路由的 meta 算进来）→ 按 path 切片段。
7. **改 `.env.local` 会让正在跑的 Vite 自动重启，端口被占时降级到 5174** —— 于是「另起一个实例」
   其实是漂移过去的旧实例，差点把验证结论弄反。（顺带把用户原本跑在 5173 的实例弄停了，已重新起回。）

> 七条里有四条属于「**测试全绿但真机不对**」：断言覆盖纯逻辑，而身份态、挂载时机、路由注册顺序
> 只有在浏览器里跑才暴露。节奏必须是「先 `test:data` 全绿，再完整走一遍浏览器」。
